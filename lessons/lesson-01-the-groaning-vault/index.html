02 · What “slow” can mean

A database has four finite resources.

Every scaling technique moves pressure away from something. If you cannot name that resource, you cannot know whether the technique worked.

01

CPU

Parsing, planning, joins, sorting, compression, and row processing consume compute.

Signalhigh utilization + runnable queue

Memory

The buffer pool keeps useful pages close. When the active set no longer fits, disk work rises sharply.

Network

03 · Three different walls

Partitioning and sharding answer different complaints.

The word “split” hides three distinct goals. Only one necessarily needs more machines.

PressureWhat hurtsFirst questionsLikely direction
Query pressureToo many pages touchedIs the access path wrong?Query + index
Lifecycle pressureOld data is costly to manageDo natural boundaries exist?Partition
Capacity pressureWrites or data exceed one hostCan ownership be divided?Shard

The Dragon Explains

“Partitioning draws walls inside one vault. Sharding builds more keeps.”

A partition can help the planner ignore irrelevant data and can turn retention into a cheap metadata operation. But every partition still shares the same machine. A shard moves ownership to another machine—and hands your application the work of finding it.
